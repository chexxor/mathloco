# Adobe Spectrum — radius & shape (domain 4)

Status: **ANSWERED — with a scale, a floor, and a nested-corner rule.** Unlike our system's two-token
pair (`--radius-control`, `--radius-card`), Spectrum names five levels and derives their values from the
**type** scale — the same logarithmic scale the type system uses. That is the divergence worth keeping
reasoned about rather than stealing.

| id | claim | kind | locator | quote | enforcement in source |
|---|---|---|---|---|---|
| S4-radius-01 | Sharp corners are the exception, not the default, and the exception has a criterion: precision that communicates meaning. | rule | `https://spectrum.adobe.com/foundations/styles/object-styles/rounding` | "Spectrum generally uses rounded corners throughout the interface. Exceptions to this rule are rare and reserved for specialized cases when precision is especially important and helps communicate meaning or improve the accuracy of a visual representation." | none stated |
| S4-radius-02 | Rounding is named by **level and job**, not by pixels: five levels mapped to component families. | token | `https://spectrum.adobe.com/foundations/styles/object-styles/rounding` | "Small controls such as checkbox, in-field button" | the levels are tokens in `packages/design-data/tokens/layout-component.tokens.json` (64,459 B, not opened); the job mapping is prose |
| S4-radius-03 | The same table puts medium on most components and small cards, large on panels, and full on buttons and avatars. | token | `https://spectrum.adobe.com/foundations/styles/object-styles/rounding` | "Most components, extra-small and small cards...Medium and large cards, panels, action boxes, select boxes, toolbars...Dialogs...Button, avatar, floating action button, search" | none stated |
| S4-radius-04 | Radii are not their own scale: they reuse the Major Second logarithmic scale of the type system. | token | `https://spectrum.adobe.com/foundations/styles/object-styles/rounding` | "Corner radius values scale using a Major Second logarithmic scale, the same scale used throughout Spectrum's type system." | none stated |
| S4-radius-05 | Nested surfaces get a **concentric** rule: the inner radius is a function of the outer radius and the gap, so a naive equal radius reads as uneven. | rule | `https://spectrum.adobe.com/foundations/styles/object-styles/rounding` | "When rounded surfaces are nested inside one another, their corner radii should adjust in proportion to the space between them. This helps maintain visually consistent gaps and creates the appearance of concentric curves." | none stated |
| S4-radius-06 | Base values are declared base, not final: the applied radius may vary per component. | behavior | `https://spectrum.adobe.com/foundations/styles/object-styles/rounding` | "The values shown are base values, and the applied corner radius may vary by component." | none stated |
| S4-radius-07 | Borders are the last resort for separation, and the alternatives are named. | rule | `https://raw.githubusercontent.com/adobe/spectrum-design-data/main/docs/s2-docs/foundations/styles/object-styles/border-width.md` | "Whenever possible, achieve separation through other techniques, like negative space and section titles, instead of using borders." | none stated |
| S4-radius-08 | Border width is declared functional, and its permitted variations are **semantic**: focus or selection. | rule | `https://raw.githubusercontent.com/adobe/spectrum-design-data/main/docs/s2-docs/foundations/styles/object-styles/border-width.md` | "Border width is a functional design choice, not a decorative one. Use a single border width throughout the interface, and only introduce variations to the thickness to communicate meaningful change, such as focus or selection." | none stated |
| S4-radius-09 | The system's answer to border width is a **count**, not a value: two widths exist for in-product UI. | token | `https://raw.githubusercontent.com/adobe/spectrum-design-data/main/docs/s2-docs/foundations/styles/object-styles/border-width.md` | "Spectrum supports two border widths that are used within in-product UI contexts." | tokens (not fetched); the count is prose |
| S4-radius-10 | Decorative width variation is refused outright, which is the same reason our system has one boundary role. | rule | `https://raw.githubusercontent.com/adobe/spectrum-design-data/main/docs/s2-docs/foundations/styles/object-styles/border-width.md` | "Avoid varying border widths solely to create visual interest or hierarchy." | none stated |
