# Adobe Spectrum — color roles & theming (domain 1)

Status: **ANSWERED — 12 rows, and this is the one domain where the system states a hard number and
ships no detector for it.** The gray system, the layer system and the theming system are documented as
*roles* (layer 1/2/elevated/pasteboard), never as hex values a build could diff; the only fetched page
that prints hex-like values at all is the background-layers table, and it prints gray token names.

Probe that establishes the enforcement half of the table (run this session, on the fetched repo tree):
`grep -iE 'contrast|a11y|accessib' spectrum-tree-paths.txt` over all 4,191 paths → **11 matches**, and
none of them is a contrast checker: `packages/design-data/fields/contrast.json` and
`packages/design-data/mode-sets/contrast.json` are a token *field* and a mode dimension,
`schemas/accessibility.schema.json` describes component accessibility declarations, and the one
a11y-shaped tool is `tools/platform-capture/e2e/site-a11y.mjs`, which was not fetched and is not a ratio
gate. So "Spectrum never deviates from this" is carried by generation, not by a check.
